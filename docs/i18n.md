# Localisation and right-to-left layout

The desktop client has one implementation of every screen. Text, number and
date formats, and the layout direction come from the locale; no code path
branches on a language. This page describes the catalogue format, how to add
a string or a language, the right-to-left rules and the known limits.

Code: `crates/ramflux-desktop-ui/src/i18n/` (catalogue lookup, locales,
plurals, bidirectional text, pseudo-locales, formatting) and
`crates/ramflux-desktop-navigation/src/direction.rs` (layout direction and
direction-aware layout primitives).

## Locales

Fifteen launch languages ship (`i18n::locale::SHIPPED`), in picker order:

| Tag | Language | Direction |
| --- | --- | --- |
| `en` | English (source) | LTR |
| `zh-CN` | Simplified Chinese | LTR |
| `zh-TW` | Traditional Chinese | LTR |
| `ja` | Japanese | LTR |
| `ko` | Korean | LTR |
| `es` | Spanish | LTR |
| `fr` | French | LTR |
| `de` | German | LTR |
| `pt-BR` | Portuguese (Brazil) | LTR |
| `ru` | Russian | LTR |
| `ar` | Arabic | RTL |
| `hi` | Hindi | LTR |
| `id` | Indonesian | LTR |
| `tr` | Turkish | LTR |
| `it` | Italian | LTR |

English and Simplified Chinese are complete. The other thirteen have every
key, with copy marked untranslated (`null`) so it shows in English, and their
own formatting data (number separators, date patterns, list and sentence
punctuation). Per-locale coverage is in [i18n-coverage.md](i18n-coverage.md),
generated by the catalogue checks.

Two pseudo-locales are selectable in developer builds only
(`cfg(debug_assertions)`):

- `en-XA` (long): accented letters, about 40 % longer, in brackets. It shows
  clipping, truncation and text that bypasses the catalogue.
- `ar-XB` (right to left): the English text mirrored and the interface laid
  out right to left. It shows, to a reader of English, what does not mirror.

### Selection

Settings › Appearance › Language offers "Follow system" and every selectable
locale, each under its own name. The choice is saved per device in the
desktop settings file and applies at once in every window, without a restart:
views observe the switch and translate again what they keep between frames
(`i18n::observe_locale`), and the layout direction follows on the next frame.

"Follow system" resolves the operating system's preferred language
(`sys-locale`) to a shipped locale by BCP 47 matching
(`i18n::locale::resolve`): the exact tag; Chinese by script and region
(`zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO` give `zh-TW`, any other Chinese gives
`zh-CN`); then the language (`pt-PT` gives `pt-BR`, `ar-EG` gives `ar`); then
English. A stored locale this build does not ship follows the system.

The system language is read when the app starts and when the choice is set to
"Follow system"; a change of the system language while the app runs is picked
up on the next start.

## Catalogue format

One flat JSON object per locale: `crates/ramflux-desktop-ui/locales/<tag>.json`.
Keys are dot-separated lowercase segments that describe intent
(`settings.appearance.language_help`), never text. Values are strings, or
`null` for a key that is not translated yet.

```json
{
  "common.cancel": "Cancel",
  "sections.groups.members.one": "%{count} member",
  "sections.groups.members.other": "%{count} members",
  "settings.backup.job.items.one": "%{done} of %{total} item"
}
```

- Placeholders are `%{name}`. Every translation takes the same placeholders
  as English.
- A plural message is a base key with one child per CLDR plural category its
  language uses: `one` and `other` in English; only `other` in Chinese,
  Japanese, Korean and Indonesian; `one`, `few`, `many`, `other` in Russian;
  `zero`, `one`, `two`, `few`, `many`, `other` in Arabic; `one`, `many`,
  `other` in French, Spanish, Italian and Portuguese (`many` is whole
  millions). The form is picked by the `count` argument (else `total`). A
  form other than `other` may leave out `%{count}` ("one message").
- Formatting data lives under `format.*`: `format.number.group`,
  `format.number.decimal`, `format.number.group_sizes` (`3`, or `3,2` for the
  Indian system), `format.percent`, `format.time`, `format.date`,
  `format.month_day`, `format.date_time` (strftime patterns), `format.list`,
  `format.join`, `format.labeled`, `format.sentences`, `format.clause`,
  `format.size.*`.
- Files are kept in canonical form: the English key order, one entry per
  line, two-space indent. The sync command below writes it.

The build (`crates/ramflux-desktop-ui/build.rs`) compiles every catalogue
into a sorted static table and fails when a catalogue is not a flat object of
strings and nulls, or when a key written as a literal in `src/` is missing
from `en.json`. A typo in a key does not compile.

### Lookup and fallback

`i18n::tr(key)`, `i18n::tr_args(key, args)` and `i18n::tr_count(key, n)`
look a key up along the chain of the current locale: the locale, its
language alone when that is another catalogue (`ar-EG` would fall back to
`ar`), then English. A locale serves a plural message only when it has every
category its language needs; otherwise the next locale serves the whole
message, with that locale's plural rule. A key that no catalogue has (a bug
the checks catch) shows as itself, never as an empty string.

GPUI Kit's own strings (menus, inputs, date pickers) use Kit's catalogue,
which knows `en`, `zh-CN`, `zh-TW` and `it`; other locales show Kit's
English.

### Formatting

`i18n::format` is the one module for dates, times, relative times
(`relative`, `day_label`), numbers (`number`, `decimal`, `percent`), byte
sizes (`bytes`, binary units) and list joins (`list`, `join`, `join_all`,
`labeled`, `clause`, `clauses`, `sentences`). Digits are Western Arabic digits
in every locale. Month and weekday names are not used in patterns: `chrono`
writes them only in English, so non-English patterns are numeric.

## Adding a string

1. Add the key and its English text to `locales/en.json`, and the Simplified
   Chinese text to `locales/zh-CN.json`.
2. Use it in code: `tr("area.screen.element")`, or `tr_args` with
   placeholders, or `tr_count` for a plural message. Never pass a literal to
   a text, label, tooltip or accessibility API, and never join translated
   parts with a fixed separator (use `i18n::join`, `list` and friends).
3. Run the sync, which adds the key as `null` to the other catalogues and
   regenerates the coverage report:

   ```sh
   RAMFLUX_LOCALES_SYNC=1 cargo test -p ramflux-desktop-ui --test locales -- --test-threads=1
   ```

4. `cargo test -p ramflux-desktop-ui --test locales` must pass.

A key built at run time (`format!("settings.section.{}", key)`) must sit
under a prefix listed in `DYNAMIC_PREFIXES` in `tests/locales.rs`, or the
unused-key check fails.

## Adding a language

1. Add a row to `SHIPPED` in `src/i18n/locale.rs`: the tag, the key of its
   own name (`locale.name.<tag>`), its direction, and the Kit locale.
2. Add `locale.name.<tag>` with the language's own name (an endonym, the same
   text in every catalogue) to `en.json` and `zh-CN.json`.
3. If the language's plural rule is not in `src/i18n/plural.rs`, add its
   CLDR rule for integers and its category list.
4. Run the sync: it creates `locales/<tag>.json` with every key `null`.
5. Fill in the `format.*` entries (CLDR data for the locale), then the copy.

No other code changes. Translation itself is done by translators in the
catalogue; product copy is never machine-translated into a shipped catalogue.

## Checks

`cargo test` (and CI, which runs it) fails on:

- a shipped locale without a catalogue, a catalogue of a locale that does not
  ship, a catalogue that is not canonical or whose keys differ from the
  English key set (with the locale's plural categories);
- untranslated or empty text in English or Simplified Chinese;
- a key used in code but missing (also a build failure), or a key that no
  code uses;
- placeholders that differ from English in any locale;
- an invalid date pattern, CJK text in English, internal card ids or
  protocol terms in any text;
- CJK text in any Rust source, a hard-coded string passed to a text API, a
  list joined with a fixed separator;
- a stale coverage report;
- a view that names a physical edge (`pl`, `pr`, `ml`, `mr`, `left`, `right`,
  `border_l`, `border_r`, `text_left`, `text_right`), a physical
  `justify_start`/`justify_end`, a fixed chevron, a fixed `flex_row`, or
  Kit's `h_flex` (`tests/rtl.rs`).

`tests/rtl_surfaces.rs` renders the conversation, two section pages and every
settings section in `ar-XB` and `en-XA`: the navigation rail must move to the
right edge in right to left, and no named element may show multi-word English
catalogue text unchanged in the long pseudo-locale. `tests/locale_fallback.rs`
covers fallback, plural forms, argument isolation, direction, the
pseudo-locales and locale formats at run time.

## Right-to-left rules

The same rules as the phones:

1. **One direction source.** The interface locale sets the layout direction
   (`direction::set_layout_direction`, called only by `i18n::set_locale`).
   Views never decide it.
2. **Mirror through the primitives.** `direction::h_flex()` is a row that runs
   from the start edge (a reversed row in right to left). GPUI's
   `justify_start`/`justify_end` are physical, so rows pack with
   `justify_row_start`/`justify_row_end` (flex-relative, they follow a
   reversed row). `DirectionalExt` gives `pad_start`/`pad_end`,
   `margin_start`/`margin_end`, `border_start_1`/`border_end_1`,
   `inset_start`/`inset_end`, `flex_row_start`, `text_start`/`text_end`.
   `forward_icon()` and `back_icon()` give the chevron for "next" and "back".
   The window root aligns text to the start edge.
3. **Identifiers stay left to right.** Codes, safety numbers, fingerprints,
   ids, scopes, hashes, URLs, account ids and recovery words are shown with
   `i18n::bidi::ltr` (a left-to-right isolate, controls removed) in an element
   with `text_ltr()`; their rows use `h_flex_ltr()` (the recovery phrase grid).
   Logs and diagnostics are left-aligned. Numbers use Western digits.
4. **Untrusted text is isolated.** Every argument substituted into a message
   is placed in a first-strong isolate when the interface is right to left or
   the argument holds right-to-left text or directional controls
   (`i18n::bidi::argument`); embedding and override controls are removed and
   the argument's own isolates are balanced, so it cannot reorder or close
   the text around it. Left-to-right text in a left-to-right interface is
   unchanged. List labels (`navigation::row::list_text`) strip every control
   and isolate the name. File names lose every directional control
   (`bidi::strip_controls`); message bodies keep the marks a writer may need.
5. **Messages follow their content.** A bubble's side follows the interface
   (own messages at the end edge), but the body's alignment and the order of
   the body and its time follow the message's own direction: the first strong
   letter, skipping mentions, links, addresses and inline code
   (`bidi::content_direction`).

## Known limits

GPUI and GPUI Kit (pinned `gpui-kit = 0.8.0`, `gpui-pre 0.3.9`) were checked
for what right to left needs:

- **Text shaping: real.** Lines are shaped by the platform (Core Text on
  macOS, `gpui-pre-apple-0.3.9/src/text_system.rs`, `layout_line`, a
  `CTLine` from an attributed string), which applies the Unicode
  bidirectional algorithm, isolates included, and joins Arabic. The base
  direction of a line is its first strong character; GPUI has no API to set
  it.
- **No layout direction in GPUI.** Taffy runs without a direction
  (`gpui-pre-0.3.9/src/taffy.rs`), and `Style` has only physical edges
  (`gpui-pre-0.3.9/src/style.rs`: `padding`, `margin`, `inset`,
  `border_widths` are left/right) and `TextAlign::{Left, Center, Right}`
  (no start/end). Mirroring is therefore done by the primitives above, in
  this client's views. A view that builds a row with `div().flex()` and no
  direction, or Kit components with built-in internal layout, do not mirror.
- **Kit components do not mirror.** Buttons with an icon and a label, menu
  items and their submenu chevrons, the dropdown chevron, inputs and text
  areas (cursor movement and placeholder alignment), scrollbars, the dock
  and resizable panels, notifications and tooltips lay out left to right
  inside (`gpui-component-0.8.0/src/`). Kit's popups are drawn outside the
  window root, so they do not inherit the start alignment.
- **Selectable message bodies** use Kit's read-only `Textarea`
  (`src/moments/message.rs`); its text is aligned by Kit, not by the
  message's direction. Bodies with formatted spans (`StyledText`) follow it.
- **A message's base direction** inside the line is Core Text's first strong
  character. A message that starts with a Latin mention or link followed by
  Arabic is aligned right (our rule) but its first line's internal order uses
  a left-to-right base. Adding a mark to the text would shift span offsets.
- **Generated catalog components** (`ramflux-desktop-navigation/src/generated/catalog.rs`:
  list rows, section headers, banners, approval controls, attachment shells)
  use fixed `flex_row()`. They are generated files under a manifest hash and
  are retired by work package A4; they are not edited here.
- **Fixed widths.** The navigation rail and other fixed-width columns clip
  long labels (seen in the `en-XA` captures of `tests/polish_shots.rs`: the
  rail's "Messages" and "Contacts" labels are cut). Layout for long
  languages (German, Russian) needs a design pass.
- **Fonts.** Bundled fonts are Hanken Grotesk and Noto Sans SC. Arabic,
  Devanagari, Hangul, Japanese kanji forms and Thai are drawn by system
  fallback; fixed line heights may clip Arabic diacritics.
- **Calendars and digits.** Gregorian calendar and Western digits in every
  locale; numeric date patterns (no month names) outside English and the CJK
  languages.
- **Untranslated copy** shows in English in thirteen locales until
  translators fill the catalogues.
